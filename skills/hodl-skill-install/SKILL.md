---
name: hodl-skill-install
description: Prepare a Hodl customer skill installation, detect the current project and runtime, and build a public-key QR handoff to Frost. Use for first-install onboarding; not for automatic publication or updating.
---

1. Detect the active project and actual client using session context and `scripts/bootstrap.py prepare`. Ask only for the customer slug unless project, runtime or repository identity is ambiguous. Executable presence does not identify the active app. Read existing `.hodl/project.json`; stop on identity conflicts. Done: exact target project, customer and runtime are known.
2. Read `references/installation.md`. Resolve the exact approved customer repo from existing project configuration or Frost's provisioning receipt, not a guessed GitHub owner. Preview preparation, then use `prepare --write` only in the authorized target scope. Done: flat project metadata exists without overwriting settings.
3. Check existing exact-repo access and scoped SSH identity. For explicitly authorized device onboarding, assist native OpenSSH setup outside the project; never overwrite an existing key, print/read its private part or bypass host-key verification. Passphrase entry is user-controlled. Done: public key and its SHA256 fingerprint are available, private key remains in SSH storage.
4. Run `scripts/bootstrap.py request` with the exact customer/repo and public-key path, using `--qr` for a new temporary PNG. Show the QR and offer the identical text for Hodl to forward to the existing authenticated Frost chat. No new endpoint, automatic message or client-string encryption. Done: request is locally generated; provisioning remains pending.
5. Wait for Frost's matching repo, read-only scope and fingerprint receipt. Verify exact-repo read access using the dedicated SSH identity and approved host-key trust. Use only the target runtime's native installation lifecycle and approved package/version. Never treat a successful Git read, CLI flag or direct skill-file read as app registration. Done: access and native install have separate evidence.
6. In the target app, confirm the plugin/skill selector entry and run a harmless explicit invocation plus per-skill preflight. Record evidence and installed version in `.hodl/install-state.json` only after observed success; capabilities go in `.hodl/capabilities-<runtime>.json`, skill overrides in `.hodl/<skillId>.json`. Done: observed registration and execution or a precise remaining gate.

Local MVP implements preparation and QR request only. It deliberately cannot generate keys, provision, install, update or uninstall. Future removal uses native uninstall and preserves `.hodl` settings and customer data by default. Keep all investment on skillId `hodl-skill-install`, never automatically on a client.
