# First-install contract 0.2.3
Owner Integracije (source), Frost (publication/provisioning). On-demand, no service. Goal: approved customer skills callable in the actual app. Missing capability/access leaves a precise resumable gate. Review first three real installs individually, weekly during the first month; next review 2026-11-16. Evidence stays in project operations, never client billing.

## State and identity
Flat mutable state: `.hodl/project.json`, `install-state.json`, `<skillId>.json`, `capabilities-<runtime>.json`. Preserve existing fields. Private keys remain outside the project in native protected SSH storage. Exclude runtime state from Git with operator visibility. Read only known paths; never scan other projects to guess identity. Existing matching project identity survives chat deletion. Customer/repository/absolute project form identity; a legacy runtime field is retained but is not an identity constraint. Preserve state and record installation evidence under `install-state.json` `runtimes.codex` or `runtimes.claude-code`. Runtime selection must match actual app evidence.

## Preflight
Before keys/network, run `python3 <bootstrap>/scripts/bootstrap.py preflight --project <project> --runtime <codex|claude-code>`. Use python/py -3 where appropriate. The helper checks OS/architecture, executing Python >=3.9, required Git/SSH/keygen executables, bootstrap resources and an actual temporary project write. It reports local QR availability; resolve a missing backend before QR, not by an external QR service. Confirm actual app/runtime/version and tool permissions from session/app evidence separately; executable presence is not app evidence. Keep unknowns explicit. Show one short result before continuing: OS, actual app, project, required tools, blockers/optional gaps. Save observed evidence under `.hodl/capabilities-<runtime>.json` after authorized preparation, preserving other fields. No browser login or PDF parser is an installation prerequisite. If Python/shell is unavailable, give the exact missing dependency; no fabricated preflight success or unsolicited package installation.

## One-way SSH provisioning
Dedicated Ed25519 key per device/repository, no passphrase by default. Use a shell tool with stdin closed and restrictive native permissions (POSIX umask 077/key 0600, Windows user-only ACL); check both paths including symlinks before creation. Reuse only a proven correctly scoped key, never read private content or overwrite/strip its passphrase. No GUI Terminal control is required.

QR contains the public request, not approval. Hodl transfers it once to authenticated Frost. Frost recomputes fingerprint, checks exact repository/duplicates, adds read-only key and re-reads GitHub `read_only=true`; this is the authority check. The customer only needs successful retrieval from the confirmed publisher repository using that dedicated key. A receipt inside the same repo adds no independent publisher authentication and is NOT an installation prerequisite. Existing receipts are optional historical audit records; never require/return them, wait for them, bind future bundle updates to an old receipt digest, or claim local read proves read-only scope. No write probes. Record `read access verified; read-only enforced by publisher provisioning` unless direct server evidence is available.

Use native Git with dedicated IdentityFile, IdentitiesOnly and normal host-key trust; always isolate configuration and agent: `ssh -F /dev/null -i <absolute-key> -o IdentitiesOnly=yes -o IdentityAgent=none` (Windows `-F NUL`). Run `ssh -T git@github.com` with those options and require the repository-specific `Hi <owner>/hodl-client-<customer>!` greeting (normal GitHub exit 1); a personal username is not deploy-key proof. Use identical options in `GIT_SSH_COMMAND` for ls-remote/clone. Unknown/mismatched GitHub host key uses normal verified trust, never StrictHostKeyChecking=no. Probe only `git@github.com:<confirmed-owner>/hodl-client-<confirmed-customer>.git`, bounded timeouts and at most 10 attempts 15 seconds apart. On failure preserve state and stop pending; retry the same identity on continuation without another QR. Clone the exact repository to a new temporary directory once readable. Record commit plus manifest digest; internal file hashes detect corruption but do not authenticate a publisher on their own. Publisher trust comes from previously confirmed repo/owner plus native host-verified transport.

## Native standalone pilot adapter
This is a project skill install, not plugin registration or a custom updater. Sources checked 2026-11-09:
- Codex project `.agents/skills/<skill>/SKILL.md`: https://learn.chatgpt.com/docs/build-skills.md
- Claude Code project `.claude/skills/<skill>/SKILL.md`, `/skill` invocation: https://code.claude.com/docs/en/skills
No equivalence to Claude chat/Cowork, remote/cloud sessions or a different desktop browser is implied. Preserve the known user bootstrap path; do not migrate legacy locations.

Run `python3 <bootstrap>/scripts/install.py --bundle <exact-repo-clone> --public-key <identity.pub> --project <project> --customer <confirmed-slug> --repository <confirmed-owner>/hodl-client-<confirmed-slug> --runtime <codex|claude-code>`. No --receipt. The adapter reads the approved skill list and exact version pins only from the verified customer manifest. Each unique safe skill ID maps to skills/<id> and a fixed native destination beneath the chosen runtime root. Multiple skills are supported; arbitrary manifest commands/hooks are never executed. No skill is known or promised before verified exact-repository retrieval. It checks identity/runtime, complete skill inventory/hashes and rejects symlinked state/targets. Identical existing skill files are a resumable no-op; changed existing files are preserved, not updated automatically. No user-wide fallback.

Try actual skill invocation in the current app first; reload/new chat only if discovery needs it. Use each verified installed ID: Codex `$<skill-id>`; Claude Code `/<skill-id>`. Follow its documented harmless local preflight or read-only help, never assume a universal preflight command. If none exists, record pending acceptance instead of executing a business action. No portal/export. Record installation acceptance only after observed invocation, not file presence. Operator-provided app output is attributed user-reported evidence, not an independent observation. Update existing install-state with versions, fingerprint, exact-repo/commit evidence, app/version, invocation evidence and time, preserving fields. Portal/login/export acceptance remains separate. No forced new chat ritual, app restart, secret export, browser settings change or package install.

## Bootstrap entry in Claude Code
Before the bare invocation, install the reviewed bootstrap from `https://github.com/tomih/hodl-skill-install` tag `v0.2.4` using existing authorized GitHub access, into `~/.claude/skills/hodl-skill-install`. Clone into a fresh temporary directory, verify SHA256SUMS, copy only `skills/hodl-skill-install`. If authentication is missing report that exact blocker; customer deploy key cannot authorize this repo. Preserve existing installations with a backup outside discovery paths; never share a symlink between apps. Updating the known Codex bootstrap path is separate, not required for Claude Code. No Mac actions by Frost. On macOS git may trigger the developer-tools dialog; report it as a system prerequisite rather than claim success.

## Resume state
Use existing saved keyPath first; new keys use `~/.ssh/hodl/<owner>__hodl-client-<customer>_ed25519`. At QR creation merge keyPath/fingerprint/repository/status=pending-provisioning into install-state. Never guess or scan legacy key paths: ask its exact location if missing. Successful invocation changes only the relevant `runtimes.<runtime>` entry to installed, preserving other app evidence and unknown fields.

First host trust: if GitHub is absent from known_hosts, obtain candidate keys with ssh-keyscan, compare their SHA256 fingerprints against GitHub's current published SSH fingerprints via an authenticated HTTPS source, then add only verified matching keys to known_hosts while preserving existing entries. A keyscan alone is not proof. Never disable checking or use accept-new. After repository-specific greeting, merge top-level status=provisioned; keep per-runtime invocation status separate.
